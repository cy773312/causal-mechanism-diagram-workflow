# Causal Mermaid Graph Audit（因果机制图图形逻辑审查）

## 概述

本 skill 的任务：**对照审计结论，逐项检查 Mermaid 初稿代码是否忠实表达了因果机制的图形逻辑，识别误表达，给出可操作修改建议。**

## 操作原则

1. 不重新生成主链
2. 不新增变量
3. 不评价选题价值，只评价图形是否忠实表达机制
4. 区分 Mermaid **语法问题**和**因果表达问题**（两类问题严重程度不同）
5. 优先检查背景条件、调节变量、替代解释是否被误放入主链
6. 必须检查最弱环节是否被可视化
7. 必须检查看不见的缺失是否被可视化
8. 输出服务于下一步"人工修改终稿"，给出逐条可执行的修改指令

---

## 输入格式

需要同时接收两类内容：

**① Mermaid 初稿代码**（来自 causal-mechanism-viz skill）

**② 审计基准**（来自 causal-mechanism-audit，用于对照检查）：
```
【主链】
【背景条件】（应在图中的处理方式）
【调节变量】（对应箭头）
【替代解释】（指向节点）
【最弱环节】（箭头标注方式）
【看不见的缺失】（问号节点位置）
```

若用户只提供 Mermaid 代码、未提供审计基准，执行**仅语法+结构检查**（检查项1、2、6），跳过对照类检查项（3、4、5），在备注中说明。

---

## 七项检查

### 检查1：背景条件是否误入主链

**错误表现**：背景条件用实线箭头连入主链，或被画成主链节点（矩形），与 X 节点并列或串联。

**正确表现**：背景条件应为椭圆节点，用虚线连向 X 或主链起点区域，视觉上位于主链上方，不参与因果传导。

**识别方式**：在代码中找到背景条件对应的节点，检查：
- 节点语法是否为 `ID(["..."])` 或类似椭圆形式？
- 连接箭头是否为虚线 `-.->` 而非实线 `-->`？
- 该节点是否出现在主链的 `-->` 序列之外？

**严重程度**：高——背景条件误入主链会使读者误以为它是因果原因，直接改变机制解释。

---

### 检查2：调节变量是否被误画为中介机制

**错误表现**：调节变量出现在主链箭头序列中（如 `X --> MOD --> M1`），或用实线箭头连向主链节点，看起来像是串联的中介环节。

**正确表现**：调节变量应**平行于**对应箭头，用虚线连向该箭头的终点节点，并在标注中注明其调节作用（如 `-. 影响强弱 .->`）。调节变量不应出现在 `X --> M1 --> M2 --> Y` 的串联序列中。

**识别方式**：找到调节变量节点，检查它是否出现在任何 `-->` 主链序列的中间位置。

**严重程度**：高——调节变量被误画为中介机制，会错误地扩展主链，混淆"影响机制强度"与"参与因果传导"的区别。

---

### 检查3：替代解释的位置与指向是否清晰

**错误表现**：
- 替代解释用实线箭头指向 Y，看起来像主链的分支原因
- 替代解释节点与主链节点视觉上无区别（相同形状、颜色）
- 替代解释指向了错误的节点（应指向 Y，却指向了中间节点，或反之）

**正确表现**：替代解释应为独立节点，用虚线箭头指向其可解释的节点（通常是 Y），视觉上与主链有明确区分（颜色或形状不同）。

**识别方式**：找到替代解释节点，检查：
- 箭头类型是否为 `-.->` 而非 `-->`？
- 节点是否有独立的 `classDef`（不与主链节点共享样式）？
- 指向节点是否符合审计基准中的说明？

**严重程度**：中——替代解释位置不清会使读者混淆主机制与竞争机制的关系。

---

### 检查4：最弱环节是否被可视化

**错误表现**：
- 最弱箭头与其他主链箭头样式完全相同，无任何区分
- 最弱箭头的节点被删除或移出主链（错误做法）
- 有文字标注"最弱"但箭头样式未改变

**正确表现**：最弱箭头应使用虚线样式（`-. 「弱」 .->`）或醒目标注，节点本身保留在主链中，只改变箭头样式。

**识别方式**：在代码中找到审计基准标记的最弱箭头（如 M1→M2），检查其 Mermaid 语法是否不同于其他主链箭头。

**严重程度**：中——最弱环节未被可视化会导致图形无法传达因果链的薄弱处，失去审计的意义。

---

### 检查5：看不见的缺失是否被可视化

**错误表现**：
- 审计结论中标记的缺失项在图中完全不存在（既无问号节点也无任何标注）
- 问号节点用了与主链节点相同的样式（矩形实线），看起来像已确认的环节
- 问号节点的位置不对（应在对应的因果链断裂处附近）

**正确表现**：缺失项应为六边形节点（`{{"？缺失项"}}`），用虚线连向其逻辑位置，视觉上与主链节点明确区分（虚线框或不同颜色）。

**识别方式**：逐一核对审计基准中标记的"需要画入图中的缺失"，在代码中找到对应节点，检查语法和位置。

**严重程度**：中——缺失项未可视化会使图形呈现一条虚假完整的因果链，掩盖实证的薄弱处。

---

### 检查6：图形复杂度是否掩盖主链

**错误表现**：
- 主链节点、背景条件、调节变量、替代解释、问号节点全部使用相同样式，视觉层级混乱
- 调节变量或替代解释数量过多，主链箭头被淹没
- 图中存在交叉线过多导致无法辨认主要路径

**正确表现**：主链应是视觉上最突出的部分（颜色更深、线条更粗或更醒目）；辅助元素（背景条件、调节变量、替代解释、问号节点）的视觉权重低于主链。

**识别方式**：检查 `classDef` 是否为不同类型的节点定义了不同样式；主链节点与辅助节点是否有视觉区分。

**严重程度**：低（不影响因果逻辑，但影响可读性）——若主链无法一眼辨认，建议拆分为主图+辅助图。

---

### 检查7：Mermaid 语法是否存在渲染风险

独立检查以下常见语法问题（与因果逻辑无关，但会导致图形无法渲染）：

| 问题 | 检查方式 | 修复方法 |
|------|---------|---------|
| 节点名含未转义的特殊字符（括号、冒号、引号） | 查看节点 `["..."]` 内是否有 `()`, `:`, `"` | 改用中文标点或删除特殊字符 |
| 节点 ID 与保留关键词冲突（如 `end`, `graph`） | 查看所有节点 ID | 改用 X, M1, Y 等简短 ID |
| 同一节点 ID 重复声明不同内容 | 全文搜索重复 ID | 统一为一个声明 |
| `classDef` 中引用了未声明的节点 ID | 核对 `class` 列表与节点声明 | 删除多余引用或补充节点声明 |
| 箭头标注含特殊字符导致解析失败 | 检查 `-. 标注 .->` 中的内容 | 用纯文字，避免 `<>`, `[]`, `{}` |

**严重程度**：高（语法错误会导致图形完全无法渲染）——语法问题优先修复，在审查报告最前列出。

## 状态判断标准

| 状态 | 含义 |
|------|------|
| ✅ | 图形表达与因果逻辑一致，无需修改 |
| ⚠️ | 存在轻微误表达或可读性问题，建议修改但不影响核心因果逻辑 |
| ❌ | 存在严重因果误表达，或语法错误导致无法渲染，必须修改 |

---

## 常见陷阱

| 错误 | 正确做法 |
|------|---------|
| 把语法正确误认为逻辑正确 | 语法和逻辑是两个独立检查维度，必须分开审查 |
| 因图形复杂建议删除调节变量或替代解释 | 复杂度问题的解法是拆图，不是删变量 |
| 给出"重新生成整张图"的建议 | 只给出逐条代码片段的修改指令，不替用户重画 |
| 对✅项也写修改建议 | ✅项不出现在修改优先级列表中 |
