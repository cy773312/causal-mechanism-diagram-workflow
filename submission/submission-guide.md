# 提交物格式指南

## 总体原则

作业需要证明的不是 AI 能画图，而是你能用 AI 暴露机制中的薄弱环节，并由自己完成最终的因果判断。因此提交物需要同时呈现结果（机制图）和过程（AI 协作记录+你的判断）。

推荐**双格式提交**：Word + GitHub repo。

## Word 文档（主提交物）

| 内容 | 位置 | 篇幅 |
|------|------|------|
| 封面信息 | 第 1 页 | 课程名/姓名/选题/日期 |
| 机制图终稿（截图） | 第 2 页 | 图片+图例说明 |
| 机制图终稿说明 | 第 3 页 | 三段，每段3-5句 |
| 三个交付思考 | 第 4-5 页 | 各150-250字 |
| 过程记录引述 | 最后一页 | "完整过程记录见以下链接" |

Word 文档保持简洁——终稿图+说明+反思即可。过程记录不需要全文复制进 Word。

## GitHub 仓库（过程记录）

将你的完整过程记录上传到自己的 GitHub 仓库，仓库结构可参考：

```
你的用户名/causal-mechanism-diagram-workflow
├── README.md
├── my-process-record.md    # 你的完整过程记录
└── assets/                 # 截图
    ├── step1-output.png
    ├── step3-mermaid-initial.png
    ├── step5-mermaid-final.png
    └── ...
```

也可以 fork 本方法论仓库后，在根目录添加自己的过程记录文件。

## 如何引用 GitHub 仓库

在 Word 最后一页写：

> "本作业的完整 AI 协作过程记录，包括每一步的输入、AI 输出和我的判断修改，见：
> github.com/你的用户名/causal-mechanism-diagram-workflow/blob/main/my-process-record.md"

## 评分检查清单

提交前逐项检查：

- [ ] 终稿图包含主链（视觉最突出）
- [ ] 背景条件在图上（椭圆+虚线，不参与传导）
- [ ] 调节变量在箭头旁（虚线连接，不是主链节点）
- [ ] 最弱环节被可视化（虚线或标注）
- [ ] 缺失项被标记（问号节点或图注）
- [ ] 图例说明清晰
- [ ] 终稿说明三段完整
- [ ] 三个反思各150-250字
- [ ] 思考一聚焦一个压缩决策
- [ ] 思考二有具体补强策略（不是"需要更多研究"）
- [ ] 思考三使用了 MCAR/MAR/MNAR 框架
- [ ] 过程记录包含你的判断（不只是 AI 输出）
- [ ] 过程记录包含你不同意 AI 的地方或你做的额外修改
- [ ] GitHub 链接在 Word 中可访问
